## 2. 아트보드 읽는 법

`design/canvas/*.dc.html`은 **정적 HTML + 인라인 스타일**입니다. 빌드 도구가 필요 없습니다.

```
<x-dc>
  <helmet> … 폰트 link + 기본 CSS … </helmet>
  <div style="width: 390px; height: 844px; …">   ← 이 최상위 div가 화면 하나
```

- 브라우저로 파일을 직접 열면 그대로 보입니다
- `design/canvas/navi-redesign.html` 하나를 열면 75장을 한 캔버스에서 봅니다
- 모바일 390×844 · 데스크톱 1440×900 · 카탈로그 시트는 세로로 긴 프레임
- 인라인 스타일의 픽셀 값을 **그대로 베끼지 말고**, `tokens.v3.json`의 토큰으로 옮기세요.
  아트보드는 토큰을 눈으로 확인하려고 펼쳐 쓴 것입니다

`screens.json`에 아트보드마다 `source` 필드가 있어 어느 파일에 해당하는지 바로 알 수 있습니다.

## 3. 작업 순서

`IMPLEMENTATION-PLAN.md`의 4단계를 그대로 따르세요. 각 단계는 독립적으로 되돌릴 수 있습니다.

1. **토큰 교체** — `globals.css` 변수와 서체. 레이아웃은 2.2 그대로. 이것만으로 색이 v3가 됩니다
2. **공통 컴포넌트** — `DataRow` · `HeroCard` · `AssumptionCard` · `RouteBar` 신규. `MetricTile`은 히어로 안 3연속 지표 전용으로 축소
3. **화면별 레이아웃** — 홈 → 자산 → 소비 → 목적지 → 미래 순서 권장. 각 화면마다 라이트/다크 아트보드가 짝으로 있습니다
4. **그래프** — Recharts. Y축 눈금 제거, 카드 폭 전체 사용, 오른쪽을 점선 예상으로 채움

**3단계를 화면 하나씩 끝내고 다음으로 가세요.** 여러 화면을 동시에 열면 공통 컴포넌트가 어긋납니다.

## 4. 절대 바꾸지 말 것

디자인 때문에 아래를 바꾸면 **작업 실패**입니다.

- **계산식** — 소비율·한도·상각·목적지 도착 시점 로직
- **거래 ID·백업 형식·반복 거래·계좌 연결·기존 기록**
- **`lib/engine/constants.ts`의 카테고리 15색·자산 5색** — 거래와 차트의 식별자입니다
- **로그인·클라우드 계정·실시간 외부 API를 새 요구사항으로 만들지 않습니다.** 외부 서비스 없이 동작해야 합니다.
  유일한 외부 의존은 웹폰트이며 **자체 호스팅**으로 오프라인 동작을 보장하세요

### 숫자의 의미 — 헷갈리면 안 되는 것

| | |
|---|---|
| 실수령 급여 vs 총수입 | 소비율의 분모는 **실수령 급여**. 총수입(급여+부수입)은 잔여자금·상환·목표 배분에 씁니다 |
| 소비율에서 제외 | **저축·투자 이체**와 **대출상환**은 소비가 아닙니다 |
| 소비 목표 60% | 통계가 아니라 **수정 가능한 계획 시작값**. 목표 0%도 유효한 값이라 미입력으로 취급하면 안 됩니다 |
| 미입력 | 회색 `—`로만 표시. **0원·0%·좋은 성과로 바꾸지 않습니다.** 급여 0원 + 부수입만 있는 상태도 마찬가지 |
| 과거 급여 | 그 달의 **마감값만** 사용. 지금 급여로 과거를 채우지 않습니다 |
| 시뮬레이션 | 저장 기록과 구분. 저장 안 되는 가정은 **보라색 + 점선 + "저장되지 않는 가정" 배지** |

### 또래 비교

앱에는 **세부 또래 통계가 내장돼 있지 않습니다.** 확인되지 않은 평균·백분위·상위 %를 만들어 보여주지 마세요.
연령 구간은 0~3 초반 / 4~6 중반 / 7~9 후반(예: 20~23 · 24~26 · 27~29)입니다.
다섯 상태(나이 미입력 / 기준 없음 / 급여·소비 부족 / 비교 가능 / 입력 연도 확인 필요)는 `PeerStates` 아트보드에 다 그려져 있습니다.

## 5. 상태를 빠뜨리지 마세요

화면만 만들고 상태를 빠뜨리는 것이 가장 흔한 실패입니다. 카탈로그 시트에 전부 그려져 있습니다.

| 아트보드 | 상태 |
|---|---|
| `EmptyStates` | 첫 시작 · 급여 미입력 · 급여 0원+부수입만 · 자산 미입력 · 거래 없음 vs 검색 결과 없음 |
| `StorageStates` | 불러오는 중 · 불러오기 실패 · 복구 파일 오류 · 샘플→내 데이터 전환 |
| `PeerStates` | 또래 카드 5종 |
| `ModalErrors` | 필수 값 미입력 · 규칙 위반 · 저장 중 · 저장 실패 · 저장 완료 · 저장 없이 닫기 |
| `Confirmations` | 삭제·초기화 확인 5종 |
| `GoalTypes` | 목적지 5유형이 각각 어떤 입력 칸을 쓰고 안 쓰는지 |
| `CoachEmpty` | 코칭에 보여줄 것이 없을 때 |

**오류는 무엇이 잘못됐는지 + 어떻게 고치는지 + 입력한 값은 어떻게 되는지 셋을 같이 말합니다.**
저장에 실패해도 입력한 값을 지우지 않습니다.

## 6. 완료 판정

아래를 전부 만족해야 끝입니다.

- [ ] `sample-data.json`을 픽스처로 넣었을 때 화면 숫자가 아트보드와 **한 자리도 다르지 않음**
- [ ] 라이트/다크 두 모드에서 레이아웃이 동일 (색만 다름)
- [ ] 5개 탭 · 모달 14종 · 상태 카탈로그 6종이 모두 도달 가능
- [ ] 390px 폭에서 가로 스크롤 없음, 1440px에서 오른쪽 열이 비지 않음
- [ ] 본문 텍스트 대비 WCAG AA(4.5:1) 통과 — 비활성 상태는 예외
- [ ] 미입력이 어디에서도 0으로 표시되지 않음
- [ ] 저장 안 되는 가정이 저장된 기록과 시각적으로 구분됨
- [ ] 계산 결과가 `design/canvas/_tools/calc/`의 스크립트 출력과 일치

### 숫자 검산

```bash
cd design/canvas/_tools/calc
python3 amort.py && python3 net.py && python3 goals.py && python3 coach.py
```

시안에 적힌 완제일·도착일·총이자는 전부 이 스크립트에서 나온 값입니다.
수치를 바꿔야 하면 **스크립트를 먼저 고치고** 결과를 화면에 옮기세요.
