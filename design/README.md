# NAVI 디자인 재설계 v3 — 방향과 원칙

작성 2026-09-08 · 대상 NAVI 2.2 (`wealth-navigator`) · 산출물은 검토용이며 원본 소스를 수정하지 않았습니다.

---

## 1. 무엇이 문제였나

현재 화면을 캡처 47장과 `DESIGN-TOKENS.md`, 소스로 확인한 결과 아쉬움의 원인은 취향이 아니라 **구조**였습니다.

| 증상 | 실제 원인 |
|---|---|
| 글자 크기·굵기가 아쉽다 | 17·18·20·21·23·26·32px가 뒤섞여 있고, 같은 역할에 서로 다른 크기가 붙어 있음. `globals.css`의 후반 재정의가 앞의 선언을 덮어 위계가 흐려짐 |
| 그래프가 짤린다 | Y축 눈금(`140만/105만/70만/35만`)이 왼쪽 폭을 크게 먹고, 월 8일 시점의 누적 그래프는 오른쪽 74%가 비어 있음. 미래 차트는 부모 CSS 높이 280px와 내부 `minHeight 300`이 충돌 |
| 꽉 차 보이지 않는다 | 모든 화면이 "가운데 정렬 라벨 → 큰 숫자 → 가운데 캡션" 타일의 반복. 데스크톱은 사이드바 224px + 가운데 한 열이라 히어로 카드 안이 비어 보임 |
| 버튼 위치가 어색하다 | `한도 조정`이 섹션 제목과 같은 줄에서 제목과 경쟁, `목표 추가`가 탭 **위**에 떠 있음, 홈 히어로 안에 CTA 두 개가 나란히 경쟁 |
| 화면이 다 비슷하다 | 홈·자산·소비·목표·미래가 전부 같은 카드, 같은 타일, 같은 크기 |

## 2. 고른 방향 — "계기판과 항로"

NAVI는 자산 성장 **내비게이션**입니다. 그래서 내비게이션 앱의 화면 문법을 은유가 아니라 **정보 구조**로 가져왔습니다.

```
현재 위치  →  항로(목적지까지의 진행)  →  다음 안내  →  목적지
57.9%        ▓▓▓▓▓▓▓┃░░░░               고금리부터    비상금 6개월
             현재    목표 60%
```

- **현재 위치** — 월급 대비 이번 달 예상 소비율. 화면당 유일한 `display` 크기 숫자.
- **항로 바** — 0%~100% 트랙 위에 현재 진행(그라디언트)과 **목적지 깃발**(목표 60%의 세로 마커). 지금까지의 얇은 진행바를 제품의 서명 요소로 승격.
- **다음 안내** — 내비의 턴 카드. 방향 아이콘 + 한 문장 지시 + 행동 하나.
- **목적지** — 목표. 링 진행률과 도착 예상 시점.

장식이 아니라 "지금 어디고, 다음에 뭘 하면 되는지"를 읽게 하는 장치입니다.

## 3. 다섯 가지 원칙

### 원칙 1 — 화면당 큰 숫자는 하나

`display`(54/62px)는 화면마다 딱 하나. 홈은 소비율, 자산은 순자산, 소비는 계획 대비 속도, 목적지는 월 배분, 미래는 10년 뒤 순자산. 나머지는 전부 `metric` 이하로 내립니다. 지금은 한 화면에 32px 숫자가 4~5개라 어느 것도 주인공이 아니었습니다.

같은 화면에 두 번째 분모가 필요할 때는 **크기로 가릅니다.** 홈의 주 지표는 `예상 소비 ÷ 월 실수령 급여`(54px)이고, `예상 소비 ÷ 순자산`(2.2%)은 캡션 줄 오른쪽 끝에 13px 보조로 붙습니다. 4배 차이라 어느 쪽이 주인공인지 한눈에 보이고, 히어로 높이는 늘지 않습니다. 급여가 비어 주 지표가 `—`인 달에도 순자산 대비는 계산되므로 미입력 카드에서 그 값을 함께 보여 줍니다.

### 원칙 2 — 가운데 정렬 타일을 데이터 행으로 바꾼다

| 지금 | v3 |
|---|---|
| 라벨(가운데) / 큰 숫자(가운데) / 캡션(가운데, 2줄로 깨짐) | 이름 왼쪽 · 금액 **오른쪽 정렬 tabular** · 비중 오른쪽 · ⋯ 메뉴 |

숫자를 오른쪽 정렬 열에 세우면 자릿수가 눈으로 비교됩니다. 가운데 정렬은 히어로의 결과값 한 곳에만 남기고, 그마저도 왼쪽 정렬로 바꿔 옆에 증감을 붙였습니다. 자산 화면은 타일 5개가 **스파크라인 + 구성 막대 + 계좌 행 리스트**로 바뀌면서 정보량이 3배가 되고 높이는 비슷합니다.

### 원칙 3 — 그래프는 카드 폭을 끝까지 쓴다

1. **Y축 눈금 제거.** 값이 필요한 지점에만 옅은 기준선 + 인라인 라벨(`한도 216만`, `1억`).
2. **빈 오른쪽을 예상선으로 채운다.** 월 8일의 누적 소비는 오늘까지 실선, 월말까지 점선. 앱이 이미 계산하는 "월말 예상 소비"를 그래프로 옮긴 것이라 새 계산이 필요 없습니다.
3. **끝점에 값 라벨.** 툴팁 없이 읽힙니다.
4. **높이 고정.** 소비 추이 150px, 미래 150px, 스파크라인 58px. 부모/자식 높이 충돌 제거.

### 원칙 4 — 행동은 그 값 옆에

| 행동 | 지금 | v3 |
|---|---|---|
| 한도 조정 | 카드 헤더에서 제목과 경쟁, 총한도·카테고리를 한 버튼으로 처리 | **`총한도 조정`** 은 총한도 숫자 바로 아래 / **`배분 편집`** 은 카테고리 목록 헤더. 둘로 분리 |
| 목표 추가 | 탭 위에 떠 있음 | 목록 **마지막**의 점선 버튼 |
| 기준 조정 | 히어로 안에서 주 CTA와 경쟁 | "실수령 급여 기준 …" 문장 **오른쪽**의 텍스트 링크 |
| 적립 | 별도 진입 | 해당 목표 **행 안쪽** 오른쪽. 적립 불가한 순자산·부채 목표에는 아예 없음 |

### 원칙 5 — 확정된 값과 가정을 색으로 가른다

- **보라 + 점선 테두리 + "저장되지 않는 가정" 배지** — 홈 소비 시나리오, 미저장 상환 계획, 목표 계산기.
- **회색 `—`** — 미입력. 0원·0%·초록(좋음)으로 절대 바꾸지 않습니다.
- 급여 0원 + 부수입만 있는 상태는 소비율을 `—`로 두고 **총수입 대비 소비**를 대안 지표로 제시합니다.

## 4. 또래 비교를 다루는 방식

앱에 세부 또래 통계가 없다는 사실을 숨기지 않고 **화면의 일부로 설계**했습니다. 5가지 상태(`PeerStates` 아트보드)를 모두 만들었고, 어느 상태에서도 확인되지 않은 평균·백분위·상위 %를 만들어 넣지 않습니다.

- 비교가 가능할 때는 **내 소비율 / 등록한 기준**을 위아래 두 개의 막대로 놓아 차이가 형태로 읽히게 했습니다. 지금의 "40px 가운데 정렬 %p 숫자"보다 정직하고 빠릅니다.
- 출처·연도·표본수를 항상 카드 안에 붙이고, "내가 직접 등록한 기준입니다. 앱에 내장된 통계나 순위가 아니에요"를 고정 문구로 둡니다.
- 비교 불가 상태에서도 개인 목표와 연결된 다음 행동은 남깁니다.
- 연령 구간은 10년 단위 안에서 0~3 초반 / 4~6 중반 / 7~9 후반을 지킵니다(예: 만 27~29세 = 20대 후반).

## 5. 데스크톱

2.2의 데스크톱은 사이드바 224px + 가운데 한 열이라 넓은 화면일수록 히어로가 비어 보였습니다. v3는 본문을 **1.6fr / 1fr** 두 열로 나눕니다.

- **왼쪽** — 주지표 히어로(숫자 왼쪽 · 보조 지표 3개 오른쪽 · 항로 바가 카드 폭 전체를 가로지름), 그리고 그래프.
- **오른쪽 레일** — 다음 안내 · 대표 목적지 · 또래처럼 "곁눈질로 보는" 정보.
- **사이드바**에 각 탭의 현재 수치(자산 9,350만 · 소비 57.9% · 미래 2.0억)와 "이번 달 남은 여유" 미니 카드를 넣어 이동 전에 상태를 읽게 했습니다.

목록형 화면(소비 내역)은 같은 골격에서 **목록 1.75fr / 요약 레일 1fr**로 바뀝니다.

## 6. 폰트

2.2는 `Pretendard`를 이름으로만 지정하고 `@font-face`가 없어 실제 서체가 OS마다 달랐습니다. v3 시안은 **IBM Plex Sans KR**(Google Fonts, 한글·라틴·tabular 숫자 한 가족)로 그렸습니다. 계기판 같은 기술적인 인상이 제품 성격과 맞습니다.

구현에서는 둘 중 하나를 고르면 됩니다. **어느 쪽이든 서체 파일을 실제로 번들해야** 웹과 Android가 같은 화면이 됩니다.

- Pretendard 자체 호스팅 유지 (시안의 크기·굵기 램프는 그대로 적용 가능)
- IBM Plex Sans KR 번들 (시안과 완전히 동일)

**× 2는 라이트와 다크입니다.** 각 화면의 다크는 라이트 바로 아래 줄에 같은 x 좌표로 놓여 있어, 페이지를 옮기지 않고 세로 스크롤만으로 두 모드를 비교할 수 있습니다. 줄 간격도 의미가 있습니다 — 라이트와 그 다크 사이는 52px, 다음 화면 묶음까지는 168px.

토큰 시트만 다크 사본이 없습니다. 이 시트는 `01 · 표면과 잉크 — LIGHT` / `02 · 표면과 잉크 — DARK` 두 절로 **라이트와 다크 값을 한 장에 나란히 적어 둔 명세**라, 다크로 변환하면 스와치는 뒤집히는데 그 아래 적힌 hex 문자열도 같이 바뀌어 서로 맞지 않는 사본이 됩니다.

아트보드 75개 전부를 헤드리스 크로미엄으로 렌더해 프레임 밖으로 넘치는 내용이 없는지 측정했습니다(현재 **75개 모두 오버플로 0**). 상태 카탈로그 3종은 이 측정에서 잘림이 드러나 프레임 높이를 늘렸습니다 — 저장소 상태 1180 → 1264, 또래 카드 1360 → 1552, 미입력 1400 → 1718.

토큰 시트 `03 · 브랜드와 상태색`에는 다섯 상태색마다 **다크 대응값**이 함께 적혀 있습니다(brand `#3556E6` → `#7FA0FF`, positive `#0F7B47` → `#3DD489`, warning `#B45309` → `#F5B544`, negative `#C0342F` → `#E8635F`, violet `#7A3FE4` → `#B79BFF`). 브랜드 그라디언트만 두 모드에서 같은 값입니다.

좌우로 나란히 놓은 비교 시트가 필요하면 `canvas/_tools/mkcompare.py`를 돌리세요. 캔버스는 위아래로 짝지어 두고, 이 도구는 한 장짜리 좌우 비교 이미지를 만듭니다.

다크는 **토큰 매핑만 다르고 레이아웃·타이포·간격은 라이트와 완전히 동일**합니다. 브랜드 그라디언트와 카테고리·자산 고정 팔레트는 다크에서도 같은 값이고, 채운 버튼만 반전됩니다(밝은 브랜드색 배경 + 어두운 글자).

예외는 **이미 반전된 요소**입니다. 저장 알림 토스트는 라이트에서도 어두운 배경에 흰 글자라 라이트/다크가 같아야 하므로, `<!--dc-keep-->`로 감싸 다크 변환에서 제외합니다.

## 8. 지킨 제약

- 계산식·거래 ID·백업 형식·반복 거래·계좌 연결·기존 기록을 바꾸지 않습니다. 시안의 수치는 전부 **가상 샘플**이며 내부 정합성만 맞췄습니다.
- 로그인·클라우드·외부 API·네트워크 필수 자산을 새로 요구하지 않습니다. 유일한 외부 의존은 웹폰트이며, 자체 호스팅으로 오프라인 동작이 가능합니다.
- 실수령 급여와 총수입 구분, 저축 이체·대출상환의 소비율 제외, 기본 목표 60%가 "수정 가능한 계획 시작값"이라는 성격, 과거 급여는 그 달 마감값만 사용, 시뮬레이션과 저장 기록의 구분을 모두 유지합니다.
- 카테고리 15색·자산 5색 고정 팔레트는 거래와 차트의 정체성이므로 2.2 값 그대로입니다.

- 실제 기기에서 30~42px 보조 버튼의 히트 영역(색 대비는 측정 완료 — AA 미달 835 → 61건, 남은 61건 중 47건은 비활성이라 요건 제외)
- 실제 데이터 볼륨(거래 수백 건, 긴 계좌명, 억 단위 금액)에서의 줄바꿈
- Recharts로 옮겼을 때의 축 라벨 제거·예상선 구현 세부

### 샘플 수치에 대해

각 화면 안에서는 수치가 맞지만, **목적지의 도착 예상일과 상환 완제일은 화면에 적힌 월 배분·월 상환액으로 다시 계산하면 딱 떨어지지 않습니다.** 여러 화면에 같은 날짜를 쓰기 위해 라벨을 맞춘 값입니다. 실제 구현에서는 엔진이 계산하므로 문제되지 않지만, 시안의 날짜를 검산 기준으로 쓰지는 말아 주세요.
