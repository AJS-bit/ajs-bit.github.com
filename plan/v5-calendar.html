§0한 줄로

홈 히어로 바로 아래에 이 달의 달력을 띄우고, 오늘 칸을 누르고 숫자만 치면 저장되게 만듭니다. 달력은 "이 달의 하루하루"를 보여 주는 카드이지, 새 계산이 아닙니다.

소비율 57.9%라는 숫자는 기록이 쌓여야 의미가 있는데, 지금은 기록 한 건에 탭 전환과 4탭이 듭니다. 이 계획은 그 거리를 홈 안에서 2탭 + 숫자로 줄이고, 그러면서도 계산식·저장 형식·보호 파일은 건드리지 않습니다.

달력은 v4 홈 구성(homeLayout.cards)의 카드 하나입니다. 다만 요청하신 것이 "홈 화면에 달력을 띄워"이므로 기본 구성에 들어가 첫 실행부터 히어로 아래 첫 카드로 보입니다. 기본 5카드는 달력 · 다음 안내 · 이번 달 한도 · 대표 목적지 · 또래와 내 페이스이고, 순자산 대비 소비는 기본에서 빠집니다(HomeSetup에서 언제든 다시 켤 수 있음). 이것은 v4 결정 2(기본 = v3 홈 그대로)를 바꾸는 일이라 v4 계획 §9에 새 결정 8번으로 올려 승인을 받습니다(§12-1). 달력을 끈 사용자도 히어로 소비 기록하기로 같은 하루 시트를 엽니다.

세 가지를 이 순서로 합니다.

  1. 하루 시트 — 홈 위에 뜨는 빠른 입력
  2. 홈 달력 카드 — 주 스트립과 이번 달 그리드, 하루 기준선
  3. 나중에 분류 — 색을 고르지 않고 저장하고, 주말에 한 번에 정리

§10의 4단계로 나눴고 각 단계는 따로 출시할 수 있습니다. 순서는 v4 1단계(홈 구성) 뒤입니다.

불편의 원인은 취향이 아니라 거리입니다.

  • 오늘 커피 한 잔에 탭 전환 1 + 탭 4(CTA → 금액 → 카테고리 → 저장) + 숫자 타이핑. 카테고리를 안 고르면 식비로 저장되는데 그 사실이 화면에 없다.
  • 어제 것을 넣으려면 날짜 필드를 열어 피커를 조작해야 한다.
  • 저장하고 나면 소비 탭에 남아서, 히어로 숫자가 어떻게 바뀌었는지 보려면 홈으로 돌아가야 한다.
  • "이번 달 어느 날을 안 적었나"를 볼 곳이 없다. 미입력 날은 그래프에서 0으로 보이는 것과 구분되지 않는다.

§2원칙 — 기존 것 그대로 + 새로 필요한 것

기존 원칙은 그대로입니다. 화면당 display 숫자 하나(홈 = 소비율) · 미입력은 0이 아니라 회색 — · 시뮬레이션(보라 점선 저장되지 않는 가정)과 저장 기록의 구분 · 계산식·거래 ID·백업 형식·반복 거래·계좌 연결·기존 기록 불변 · 로그인·클라우드·실시간 외부 API 없음 · 고정비(주거·통신·보험·구독)는 실제 청구액을 인정하고 변동비만 조절, 월말 예상은 고정비/변동비를 나눠 추정 · 저축 이체·대출상환은 소비율에서 제외 · 카테고리 15색 고정 팔레트는 거래·차트를 구분하는 기준색.

이 계획에서 새로 필요한 원칙 여섯 개:

  • 하루의 표시는 규칙 한 문장으로 정한다. 달력 칸 = 변동비 합계 + 막대, 고정비·이체는 배지 고정·이체. 내역 날짜 그룹 헤더 = 변동 3.2만 · 고정 55만 · 이체 30만. 같은 날을 두 숫자로 보여 주지 않는다. (§3-3)
  • 안 썼어요는 기록이 아니라 표시다. 거래를 만들지 않고 dayLog에만 남는다. 소비율·월 비교·코치·경고는 그것을 보지 못하며, 화면은 그 사실을 숨기지 않는다. (§8)
  • 화면 문구가 계산과 어긋나지 않는다. 나중에 분류는 계산에서 기타(변동비)다. 지난달 기록은 이번 달 예상의 3개월 평균에 들어간다. 문구는 이 사실을 그대로 쓴다. 이번 달에는 안 들어가요 같은 약속을 하지 않는다. (§5-3, §8)
  • 기록에 평가를 붙이지 않는다. 완료 카드는 초과 여부와 무관하게 사실만(오늘 N건 · 합계 · 소비율 변화), 색 없음. 연속 카운터 없음. 주황은 사용자가 정한 월 목표 초과(히어로)에만. 요청에서 말씀하신 "중압감"은 히어로 소비율 하나가 주고, 달력 칸과 완료 카드는 기록을 가볍게 하는 쪽에 섭니다 — 둘이 부딪히는 지점이라 §12-19에서 결정합니다. (§3-3, §4-4)
  • 계산은 한 곳에서만. 시트와 완료 카드가 보여 주는 소비율은 전부 naviMetrics의 결과다. UI에서 따로 더하지 않는다. (§4-5)
  • 보호 파일은 읽기만 한다. lib/engine/** · navi-current · navi-storage · navi-recurring 등 IMPLEMENTATION-PLAN §2의 파일은 수정하지 않는다. 하루 기준선·하루 합계·분류 전 정리는 새 모듈 lib/navi-quick-entry.ts가 그 파일들의 반환값을 받아 계산한다. (§6, §10)

§3홈 화면

3-1. 달력의 자리 — homeLayout의 첫 카드

달력은 v4 §3·§6의 homeLayout.cards에 들어가는 카드 calendar(이름 이번 달 달력)입니다. 히어로 아래 고정 슬롯이 아니라 카드 하나이고, 히어로만 고정이라는 v4 결정 3은 그대로입니다. 다만 요청("홈 화면에 달력을 띄워, 날짜를 터치해서 바로 입력")에 맞춰 기본 구성에 들어가고, 히어로 바로 아래 첫 카드입니다.

  • 기본 5카드 = 달력 · 다음 안내 · 이번 달 한도 · 대표 목적지 · 또래와 내 페이스(homeLayout.cards 기본 배열 ["calendar","nextGuide","limit","primaryGoal","peer"]). 카드 상한 5를 지키느라 순자산 대비 소비가 기본에서 빠지고, HomeSetup 목록에는 남아 언제든 다시 켤 수 있습니다.
  • 이 변경은 v4 결정 2("기본 = v3 홈 그대로")와 v4 완료 기준 "아무것도 안 고르면 v3 홈 그대로"를 바꾸는 일이라 v4 계획 §9에 새 결정 8번으로 올려 별도 승인을 받습니다(§12-1). 이 문서의 표 한 줄로 승인된 결정을 뒤집지 않습니다.
  • 기본 배열만 바뀝니다. 이미 homeLayout.cards를 저장한 사용자의 구성은 건드리지 않고, HomeSetup 첫 행에서 켜면 들어갑니다.
  • HomeSetup 목록에서 이번 달 달력 행은 기본 켜짐 상태로 첫 행에 있고 축소 미리보기(주 스트립)가 붙습니다.
  • 달력을 끈 사용자에게도 히어로 소비 기록하기는 오늘 하루 시트를 엽니다(§3-4). 상태 줄 전용 안내는 소비 탭 알림 줄이 대신합니다(§8, §12-29).

3-3. 날짜 칸이 보여주는 것

하루 표시 규칙(한 문장): 칸의 숫자와 막대는 그날 변동비 합계(분류 전 포함)이고, 고정비와 이체는 숫자에 넣지 않고 배지 고정·이체로만 표시한다. 내역 날짜 그룹 헤더는 변동 3.2만 · 고정 55만 · 이체 30만으로 셋을 나눠 쓴다(0인 항목은 생략).

칸 숫자 형식(한 형식): 만 단위 소수 한 자리. 0.5만 · 3.7만 · 12.5만. 1만 미만도 같은 단위(0.9만). 100만 이상은 소수 없이 120만, 1,000만 이상 1,200만, 1억 이상 1.2억. 개별 거래는 시트·내역에서 원 단위 그대로(8,900원). 이 예외를 SPEC typography.rules에 달력 칸 합계 항목으로 등록합니다.

반올림(한 규칙, §12-23): 만 단위 소수 한 자리는 500원에서 올립니다(11,500 → 1.2만, 11,499 → 1.1만). 원 단위로 보여 주는 계산값(하루 기준선 · 앞으로 하루 · 코치)은 10원 반올림(47,272.7 → 47,270), 개별 거래 금액과 남은/초과 금액은 원 단위 그대로(11,500원 남았어요).

기본 상태 4 × 수식어 5. 조합은 표의 규칙대로만 생기고, 아트보드는 기본 상태 4장 + 수식어 5장 + 대표 조합 3장(라이트·다크 짝)으로 끝냅니다.

4-4. 완료 카드

저장이 끝나면 시트가 닫히고 홈 위에 완료 카드가 뜹니다. 전역 저장 토스트의 자리와 역할을 그대로 이어받는 Toast 변형(SPEC §19)이며, commit에 notice: 'quick' 옵션을 넘겨 이 기기에 저장했습니다. 토스트를 생략합니다. 저장 확인 UI는 하나입니다.

│ 오늘 5건 4.9만원 · 소비율 57.9% → 58.2%                     │
│ [한 건 더]   [되돌리기]                                      │
└────────────────────────────────────────────────────────────┘
  • 자동으로 닫히지 않습니다. 닫기·다음 저장·다른 탭 이동까지 유지 — 현행 되돌리기 수명과 같습니다. 되돌리기는 이 카드 하나뿐이고 대상은 전역 undoState(직전 1회분 전체 상태)입니다.
  • 제목 3종, 카드는 하나: 하루 시트 저장 저장했어요 · 수정 모드 저장 고쳤어요 · 분류하기 저장 분류했어요 · 7건. 뒤의 둘은 행동이 되돌리기뿐입니다(§12-2).
  • 행동 슬롯 2개 = 주 행동 + 되돌리기. 주 행동은 기본 한 건 더이고, 월급 미입력이면 월급 넣기 ›가 그 자리를 대신합니다(다음 건은 오늘 칸으로). 그 밖의 링크는 셋째 줄 문장 안에 둡니다(§12-30).
  • 반복 거래 자동 생성(focus·15분 타이머)과 dataMode 감지 저장은 notice: 'silent'로 commit해 undoState와 문구를 갱신하지 않습니다. 한 건 더 중에 앱을 전환해도 되돌리기 대상은 사용자의 저장입니다.
  • 사실만 씁니다. 초과·미달 평가어 없음, 색 없음. 둘째 줄의 소비율은 저장 전·후 naviMetrics 값입니다(편의점 12,000원 저장 → 4건 3.7만원이 5건 4.9만원, 57.9%가 58.2%). 월급 미입력이면 소비율 — 대신 주 행동이 월급 넣기 ›가 됩니다.
  • 조건부 셋째 줄은 한 줄만, 우선순위는 이 순서: 마감된 달 8월 다시 마감 › > 지난달 8월 합계와 최근 3개월 평균이 바뀌어 이번 달 예상도 달라질 수 있어요 > 지난달 첫 입력 기록이 적어 예상 방식이 바뀌어요 > 0~5시에 오늘로 저장 어제로 옮기기 › > 분류 전 저장 고정비면 분류해야 예상이 맞아요 > 고정비 색으로 저장 매달 반복으로 만들기 › > 첫 달 기록이 적어 예상 폭이 커요.
  • 한 건 더는 같은 날짜로 비워진 시트를 엽니다.
  • dayLog 저장(닫기·안 썼어요)은 카드 없이 체크 표시 자체가 확인입니다(notice: 'silent'). 실패·충돌일 때만 상태 줄에 문구가 뜹니다.

4-5. 소비율 미리보기 — 저장 전에는 보여 주지 않는다

시트 안에서 저장 전 소비율을 보여 주는 값은 정의상 저장되지 않는 값이라 원칙 5에서는 보라입니다. 원칙을 고치지 않고, 미리보기를 두지 않습니다. 히어로 변화는 저장 뒤 완료 카드의 57.9% → 58.2%로만 봅니다. 대안(§12-9)으로 조건 문구 저장하면 58.2%가 돼요를 두는 경우에도 값은 가상 AppState(saveTransaction(state, draft) 결과)에 naviMetrics를 호출해 얻고 150ms 디바운스합니다. 단순 산술로 따로 계산하는 안은 없습니다 — 고정비 max 규칙과 첫 달 선형 외삽 때문에 저장 후 값과 어긋납니다.

4-6. 수정 모드

시트 목록의 행을 탭하면 같은 시트가 수정 모드로 바뀝니다.

  • 금액 필드가 전체 선택된 채 포커스되어 타이핑이 값을 덮어씁니다(오타 수정 4탭).
  • 헤더에 ‹ 어제로 · 다음 날로 › 날짜 이동. 잔액 연결이 없는 거래는 제한 없이, 연결 거래는 날짜 잠금.
  • 잔액 연결이 있는 거래는 금액·메모·색만 바꿉니다. saveTransaction이 기존 링크로 잔액을 재계산하고 부족 예외가 나면 연결된 계좌 잔액이 부족해요 · 거래 추가에서 확인. 링크 추가·해제는 거래 추가에서만.
  • 저장하면 완료 카드 고쳤어요 · 9월 3일, 행동은 되돌리기만(§4-4).
  • 삭제는 기존 확인 대화. 반복 거래면 recurringExclusions에 등록됩니다.
  • 분류 전 행의 ⋯ 메뉴에는 매달 반복으로 만들기가 없습니다.

5-1. 색 ↔ 카테고리 매핑 규칙

요청하신 "카테고리는 색상으로 지정"은 하루 시트의 색 칩(색 점 8px + 이름)으로 구현합니다 — 색을 고르는 것이 곧 카테고리를 고르는 것이고, 이름을 붙여 색만으로 뜻을 전하지 않습니다. 달력 칸에는 카테고리색을 쓰지 않는데, 주거 #8b5cf6·구독 #a855f7이 가정 보라 #7A3FE4와 같은 계열이라 44px 칸의 8px 점으로는 구분되지 않고, 칸이 전할 정보는 변동비 합계 + 막대 하나로 끝나기 때문입니다.

불변식 세 개(전부 lib/navi-quick-entry.ts에서):

  1. 카테고리가 기타가 아니면 표식을 제거한다. 하루 시트 수정 모드·분류하기·소비 탭 거래 추가 어느 경로로 바꿔도 같은 함수(reconcileUncategorized)가 changeState 직전에 돕니다.

  3. 표시는 실시간 교집합만. uncategorized ∩ transactions(category === '기타').

골라서 가져오기는 settings 네 키만 합치므로(mergeNaviImport) 가져온 분류 전 건은 영구 기타가 됩니다. 가져오기 화면에 그 사실을 씁니다(§8).

§11완료 기준

  • 아무것도 안 고르면 홈에 이번 달 달력 카드가 히어로 바로 아래 첫 카드로 보이고, 기본 5카드가 §3-1과 같다(순자산 대비 소비는 HomeSetup에서 다시 켤 수 있음). 이미 저장된 홈 구성은 바뀌지 않는다. 끄면 카드만 사라지고 히어로 소비 기록하기는 오늘 시트를 연다
  • 월급 입력 상태에서, 홈에서 오늘 커피 저장까지 2탭 + 숫자, 탭 전환 0, 저장 후 홈에 그대로 있고 완료 카드에 소비율 전·후가 보인다(탭 수 정의는 §4-1)
  • 월급 미입력 상태에서는 저장이 되고 완료 카드 주 행동이 월급 넣기 ›다
  • 최근 기록 칩으로 3탭, 숫자 0. 분류 전 건도 분류 전 라벨 칩으로 쓸 수 있다
  • 어제·그저께 기록에 날짜 피커 없음. 지난달은 헤더 날짜 탭의 주 선택기로
  • 시트에 거래 종류·잔액 반영·계좌 선택이 없고, 저축·상환·수입·환불은 거래 추가로 값을 들고 넘어갔다가 홈으로 돌아온다
  • 미입력 칸은 —, 안 썼어요는 0, 둘은 끝까지 다른 상태. 고정비·이체만 있는 날은 — + 배지. 안 썼어요는 변동비 0건이면 누를 수 있다. 0원 거래는 만들지 않는다. 안 썼어요는 소비율·월 비교·코치·경고에 영향이 없고 화면에 그 사실을 표시한다
  • 칸 숫자·막대는 변동비만. 고정비는 고정, 이체는 이체 텍스트 배지. 셀에 카테고리 색 사용 없음
  • 칸 숫자는 한 형식(0.9만 · 3.7만 · 12.5만 · 120만 · 1,200만 · 1.2억), 반올림은 500원 올림·10원 반올림 한 규칙, 기본 글자 크기에서 7자리 금액도 44px 안에 들어간다. 글자 확대 시 글자를 줄이지 않고 §8 넘침 규칙을 따른다
  • 주 스트립은 오늘이 속한 일~토, 펼침 토글은 펼치기 ▾/접기 ▴이고 이번 주가 두 번 그려지지 않는다. 미래 칸과 다음 달 칸은 disabled에 숫자 자리가 빈 칸이다
  • 화면당 display 숫자 하나(히어로), 그림자 카드 하나, 채운 Primary 하나(소비 기록하기 · 시트 안은 저장)
  • 달력·시트·완료 카드 어디에도 보라·점선 없음. 보라는 저장되지 않는 가정 카드에서만. 저장 전 소비율 미리보기 없음
  • 주황은 히어로의 월 목표 초과에만. 칸의 기준선 초과는 막대 꽉 참 + 숫자, 분류 전 강조 표시는 굵기 + brand-soft
  • 색만으로 전달하는 상태 없음 — 칩은 점 + 이름, 칸은 막대 + 숫자, 빨강 없음
  • 상태 줄은 항상 한 문장, 평가어·알림 없음. 18시 이후 다 적었어요는 오늘 요약 문장에 합쳐 1탭으로 보인다. 연속 카운터 없음, 이번 달 기록한 날 N일은 수동 변동비 거래 1건 이상인 날만. 달력 카드가 없으면 같은 안내가 소비 탭 알림 줄에 뜬다
  • 완료 카드는 사실만(N건 · 합계 · 소비율 전후), 색 없음, 자동 닫힘 없음. 제목 3종(저장·고침·분류)에 카드는 하나, 행동 슬롯은 주 행동 + 되돌리기. 되돌리기 진입점은 하나이고 수명은 현행(닫기·다음 저장까지). 자동 생성 저장은 undoState를 갱신하지 않는다
  • 나중에 분류는 기타로 저장되고 소비 합계·한도 총액이 즉시 정확하다. 월말 예상은 변동비 가정이며 화면에 그 사실을 표시한다. 분류 전 비율(이번 달 소비 거래 대비)은 로컬 계산값으로 §12-10 강조 표시 조건에만 쓴다 — 서버·분석이 없어 완료 지표로 삼지 않는다
  • 고정비 색으로 바꾸거나 지난달에 저장하면 히어로가 바뀔 수 있고, 완료 카드가 그 변화를 숨기지 않는다
  • 분류하기에서 같은 메모 4건이 한 탭에 정해지고, 추천은 탭 없이는 채워지지 않는다
  • 저장·닫기·분류 전부 changeState → saveGate 경로, 저장 중 inert
  • 옛 백업이 그대로 열리고, 새 백업을 옛 앱이 열어도 거래가 그대로다. quickEntry가 깨져도 검증기를 통과하고 getter가 정화한다
  • lib/engine 변경 0 · IMPLEMENTATION-PLAN §2 보호 파일 변경 0(SHA-256 동일) · 계산 결과 변화 0 · 거래 id·백업 형식·반복 규칙 형식 불변
  • 기존 테스트 전부 통과 + 새 케이스 추가. pnpm typecheck / test / build 통과
  • 360×640에서 본문 가로 스크롤 없음, 칸 터치 44 이상(44.6), 메모 포커스 시 저장 버튼이 키보드 위에 보인다

  • 칸은 button, 화살표 이동, focus ring 3px, aria 문장 템플릿 하나. 하루 시트는 Android 뒤로가기·Escape로 닫힌다
  • 라이트·다크 모두 토큰 값으로 렌더, 새 hex 0, darken.py 산출과 어긋나지 않음
  • 비행기 모드에서 전부 동작. 로그인·서버·외부 API 없음
