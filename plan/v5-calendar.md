# NAVI v5 계획 — 홈 달력과 빠른 소비 입력

## 0. 한 줄로

**홈 히어로 바로 아래에 이 달의 달력을 띄우고, 오늘 칸을 누르고 숫자만 치면 저장되게 만듭니다. 달력은 "이 달의 하루하루"를 보여 주는 카드이지, 새 계산이 아닙니다.**

소비율 57.9%라는 숫자는 기록이 쌓여야 의미가 있는데, 지금은 기록 한 건에 탭 전환과 4탭이 듭니다. 이 계획은 그 거리를 홈 안에서 2탭 + 숫자로 줄이고, 그러면서도 계산식·저장 형식·보호 파일은 건드리지 않습니다.

달력은 v4 홈 구성(`homeLayout.cards`)의 카드 하나입니다. 다만 요청하신 것이 "홈 화면에 달력을 띄워"이므로 **기본 구성에 들어가 첫 실행부터 히어로 아래 첫 카드로 보입니다.** 기본 5카드는 `달력 · 다음 안내 · 이번 달 한도 · 대표 목적지 · 또래와 내 페이스`이고, `순자산 대비 소비`는 기본에서 빠집니다(HomeSetup에서 언제든 다시 켤 수 있음). 이것은 v4 결정 2(기본 = v3 홈 그대로)를 바꾸는 일이라 v4 계획 §9에 새 결정 8번으로 올려 승인을 받습니다(§12-1). 달력을 끈 사용자도 히어로 `소비 기록하기`로 같은 하루 시트를 엽니다.

세 가지를 이 순서로 합니다.

1. 하루 시트 — 홈 위에 뜨는 빠른 입력
2. 홈 달력 카드 — 주 스트립과 이번 달 그리드, 하루 기준선
3. 나중에 분류 — 색을 고르지 않고 저장하고, 주말에 한 번에 정리

§10의 4단계로 나눴고 각 단계는 따로 출시할 수 있습니다. 순서는 v4 1단계(홈 구성) 뒤입니다.

## 1. 지금 앱의 소비 입력 — 사실과 불편의 원인

| 사실 | 어디서 확인 |
|---|---|
| 소비 기록은 소비 탭의 `거래 추가` 시트 하나뿐. 홈 히어로의 `소비 기록하기`는 `navigate('spending','record')`로 **탭을 옮긴 뒤** 시트를 연다 | `app/page.tsx:1041`, `home-hero.tsx:110` |
| 시트 순서: 거래 종류 세그먼트 → 날짜/금액 → 카테고리 칩 13개 → 메모 → 잔액 반영 토글. 기본 카테고리는 `식비`, 기본 날짜는 오늘(지난 달 보기 중이면 1일) | `spending-view.tsx:225-227` · v3 아트보드 `TransactionAdd` |
| 저장은 `saveTransaction`(금액 > 0 필수) → `changeState` → `materializeRecurringTransactions` → `saveGate.run` → `saveNaviData`. 성공하면 토스트 `이 기기에 저장했습니다.` + 되돌리기(닫기 또는 다음 저장 전까지 유지) | `navi-state.ts:65`, `app/page.tsx:208-232, 2351-2381` |
| 하루 단위로 보는 화면이 없다. 내역은 날짜 그룹 목록, 이번 달 탭은 일별 누적 그래프뿐 | `spending-ledger.tsx`, `navi-analysis.ts:6` |
| 월말 예상은 `metrics()`가 직전 3개월 평균으로 만든다: `projected = max(cur.fixed, hist.fixed) + cur.variable + remain × hist.variable`. 3개월이 비어 있으면 `spend ÷ done × days` 선형 외삽 | `lib/engine/finance.ts:66-76, 113-122` |
| 반복 거래는 결제일이 지나면 focus·15분 타이머에서 자동 생성되고, 그 저장도 같은 commit을 타서 토스트와 되돌리기를 갈아치운다 | `navi-recurring.ts:138-192`, `app/page.tsx:296-311` |

불편의 원인은 취향이 아니라 **거리**입니다.

- 오늘 커피 한 잔에 **탭 전환 1 + 탭 4**(CTA → 금액 → 카테고리 → 저장) + 숫자 타이핑. 카테고리를 안 고르면 `식비`로 저장되는데 그 사실이 화면에 없다.
- 어제 것을 넣으려면 날짜 필드를 열어 피커를 조작해야 한다.
- 저장하고 나면 소비 탭에 남아서, 히어로 숫자가 어떻게 바뀌었는지 보려면 홈으로 돌아가야 한다.
- "이번 달 어느 날을 안 적었나"를 볼 곳이 없다. 미입력 날은 그래프에서 0으로 보이는 것과 구분되지 않는다.

## 2. 원칙 — 기존 것 그대로 + 새로 필요한 것

기존 원칙은 그대로입니다. 화면당 display 숫자 하나(홈 = 소비율) · 미입력은 0이 아니라 회색 `—` · 시뮬레이션(보라 점선 `저장되지 않는 가정`)과 저장 기록의 구분 · 계산식·거래 ID·백업 형식·반복 거래·계좌 연결·기존 기록 불변 · 로그인·클라우드·실시간 외부 API 없음 · 고정비(주거·통신·보험·구독)는 실제 청구액을 인정하고 변동비만 조절, 월말 예상은 고정비/변동비를 나눠 추정 · 저축 이체·대출상환은 소비율에서 제외 · 카테고리 15색 고정 팔레트는 거래·차트를 구분하는 기준색.

이 계획에서 새로 필요한 원칙 여섯 개:

- **하루의 표시는 규칙 한 문장으로 정한다.** 달력 칸 = 변동비 합계 + 막대, 고정비·이체는 배지 `고정`·`이체`. 내역 날짜 그룹 헤더 = `변동 3.2만 · 고정 55만 · 이체 30만`. 같은 날을 두 숫자로 보여 주지 않는다. (§3-3)
- **`안 썼어요`는 기록이 아니라 표시다.** 거래를 만들지 않고 `dayLog`에만 남는다. 소비율·월 비교·코치·경고는 그것을 보지 못하며, 화면은 그 사실을 숨기지 않는다. (§8)
- **화면 문구가 계산과 어긋나지 않는다.** `나중에 분류`는 계산에서 `기타`(변동비)다. 지난달 기록은 이번 달 예상의 3개월 평균에 들어간다. 문구는 이 사실을 그대로 쓴다. `이번 달에는 안 들어가요` 같은 약속을 하지 않는다. (§5-3, §8)
- **기록에 평가를 붙이지 않는다.** 완료 카드는 초과 여부와 무관하게 사실만(오늘 N건 · 합계 · 소비율 변화), 색 없음. 연속 카운터 없음. 주황은 사용자가 정한 월 목표 초과(히어로)에만. 요청에서 말씀하신 "중압감"은 히어로 소비율 하나가 주고, 달력 칸과 완료 카드는 기록을 가볍게 하는 쪽에 섭니다 — 둘이 부딪히는 지점이라 §12-19에서 결정합니다. (§3-3, §4-4)
- **계산은 한 곳에서만.** 시트와 완료 카드가 보여 주는 소비율은 전부 `naviMetrics`의 결과다. UI에서 따로 더하지 않는다. (§4-5)
- **보호 파일은 읽기만 한다.** `lib/engine/**` · `navi-current` · `navi-storage` · `navi-recurring` 등 IMPLEMENTATION-PLAN §2의 파일은 수정하지 않는다. 하루 기준선·하루 합계·분류 전 정리는 새 모듈 `lib/navi-quick-entry.ts`가 그 파일들의 반환값을 받아 계산한다. (§6, §10)

## 3. 홈 화면

### 3-1. 달력의 자리 — homeLayout의 첫 카드

달력은 v4 §3·§6의 `homeLayout.cards`에 들어가는 **카드 `calendar`**(이름 `이번 달 달력`)입니다. 히어로 아래 고정 슬롯이 아니라 카드 하나이고, 히어로만 고정이라는 v4 결정 3은 그대로입니다. 다만 요청("홈 화면에 달력을 띄워, 날짜를 터치해서 바로 입력")에 맞춰 **기본 구성에 들어가고, 히어로 바로 아래 첫 카드**입니다.

- 기본 5카드 = `달력 · 다음 안내 · 이번 달 한도 · 대표 목적지 · 또래와 내 페이스`(`homeLayout.cards` 기본 배열 `["calendar","nextGuide","limit","primaryGoal","peer"]`). 카드 상한 5를 지키느라 `순자산 대비 소비`가 기본에서 빠지고, HomeSetup 목록에는 남아 언제든 다시 켤 수 있습니다.
- 이 변경은 v4 결정 2("기본 = v3 홈 그대로")와 v4 완료 기준 "아무것도 안 고르면 v3 홈 그대로"를 바꾸는 일이라 v4 계획 §9에 **새 결정 8번**으로 올려 별도 승인을 받습니다(§12-1). 이 문서의 표 한 줄로 승인된 결정을 뒤집지 않습니다.
- 기본 배열만 바뀝니다. 이미 `homeLayout.cards`를 저장한 사용자의 구성은 건드리지 않고, HomeSetup 첫 행에서 켜면 들어갑니다.
- HomeSetup 목록에서 `이번 달 달력` 행은 기본 켜짐 상태로 첫 행에 있고 축소 미리보기(주 스트립)가 붙습니다.
- 달력을 끈 사용자에게도 히어로 `소비 기록하기`는 오늘 하루 시트를 엽니다(§3-4). 상태 줄 전용 안내는 소비 탭 알림 줄이 대신합니다(§8, §12-29).

### 3-2. 배치와 높이 예산

```
┌ 이번 달 달력                                  펼치기 ▾ ┐   카드 제목 14/600 · 토글 버튼(펼치면 `접기 ▴`)
│   일     월     화     수     목     금     토          │   요일 11/500 ink-3
│   6      7      8      9     10     11     12          │   날짜 11/500 · 오늘 칸 배경 brand-soft · 미래 날짜 disabled
│  0.5만  1.2만  3.7만                                    │   합계 11/600 tabular · 미래 칸은 숫자 자리가 빈 칸(`—` 아님)
│  ▂▂     ▃▃    ▇▇▇▇                                     │   막대 3px · track 위 ink-3 채움
│  ✓      고정                                           │   수식어 11px ink-2
│ 오늘 4건 3.7만원 · 이번 달 기록한 날 7일                  │   상태 줄 11/400 ink-2 · 한 문장
└──────────────────────────────────────────────────────────┘
```

| 항목 | 390px | 360px(390 미만 예외) |
|---|---|---|
| 화면 패딩 | 14 | 14 |
| 카드 좌우 패딩 | 14 | **10** |
| 칸 폭(7열, 간격 0) | (390−28−28)÷7 = **47.7** | (360−28−20)÷7 = **44.6** |
| 칸 높이 | 56 | 56 |
| 접힌 카드 높이 | 13 + 20 + 8 + 14 + 4 + 56 + 8 + 18 + 13 = **154** | 154 |
| 펼침(월 그리드) | 스트립 행이 그리드 안 자기 자리로 들어가고 나머지 4~5행이 더해짐: 154 + (4~5) × 56 = **378~434** | 같음 |

- **주 스트립은 오늘이 속한 일~토**(그리드와 같은 행). 오늘이 일요일이면 미래 칸 6개가 빈 칸으로 남습니다(§12-14).
- **펼침 토글**은 제목 오른쪽 `펼치기 ▾`/`접기 ▴` 버튼 하나입니다. 링크 모양이 아니라 토글이고, 펼치면 이번 주 행이 그리드 안 자기 자리에 놓여 두 번 그려지지 않습니다. 펼침은 카드 안에서 아래로 늘어나 홈 스크롤에 얹힙니다.
- 펼침 상태는 세션 안에서만 기억합니다(홈을 떠났다 돌아와도 유지, 앱을 다시 열면 접힘 · §12-27).
- 칸 터치 표적은 두 폭 모두 44 이상입니다(`accessibility.minTouchTarget` 44). 상태 줄은 접힘·펼침 어디서나 마지막 한 줄입니다.
- 시스템 글자 크기를 키우면 칸 글자를 줄이지 않습니다. 칸 높이가 자동으로 늘고, 44.6px 폭에서 합계·배지가 넘치면 1단계로 소수를 버리고(`3.7만` → `4만`), 그래도 넘치면 숫자를 숨기고 막대·배지만 남깁니다(숫자는 aria·시트·상태 줄에 있음 · §12-28).

### 3-3. 날짜 칸이 보여주는 것

**하루 표시 규칙(한 문장):** 칸의 숫자와 막대는 그날 **변동비 합계**(분류 전 포함)이고, 고정비와 이체는 숫자에 넣지 않고 배지 `고정`·`이체`로만 표시한다. 내역 날짜 그룹 헤더는 `변동 3.2만 · 고정 55만 · 이체 30만`으로 셋을 나눠 쓴다(0인 항목은 생략).

**칸 숫자 형식(한 형식):** 만 단위 소수 한 자리. `0.5만` · `3.7만` · `12.5만`. 1만 미만도 같은 단위(`0.9만`). 100만 이상은 소수 없이 `120만`, 1,000만 이상 `1,200만`, 1억 이상 `1.2억`. 개별 거래는 시트·내역에서 원 단위 그대로(`8,900원`). 이 예외를 SPEC `typography.rules`에 `달력 칸 합계` 항목으로 등록합니다.

**반올림(한 규칙, §12-23):** 만 단위 소수 한 자리는 500원에서 올립니다(11,500 → `1.2만`, 11,499 → `1.1만`). 원 단위로 보여 주는 계산값(하루 기준선 · 앞으로 하루 · 코치)은 10원 반올림(47,272.7 → 47,270), 개별 거래 금액과 남은/초과 금액은 원 단위 그대로(`11,500원 남았어요`).

**기본 상태 4 × 수식어 5.** 조합은 표의 규칙대로만 생기고, 아트보드는 기본 상태 4장 + 수식어 5장 + 대표 조합 3장(라이트·다크 짝)으로 끝냅니다.

| 기본 상태 | 칸 | 뜻 |
|---|---|---|
| `—` | 날짜 + `—`(disabled) | 미입력. 변동비 거래도 표시도 없음. **고정비·이체만 있는 날도 `—`**에 배지가 붙은 상태 |
| `0` | 날짜 + `0`(ink-2) | `안 썼어요`로 표시한 날. 변동비 거래 없음. **저장된 0원이 아니라 안 씀 표시.** 고정비·이체 배지는 함께 붙을 수 있음 |
| 금액 | 날짜 + 합계 + 막대 | 변동비 거래가 1건 이상 |
| 금액 + `✓` | 위 + 체크(ink-2) | 그 날짜를 `다 적었어요`로 닫음 |

| 수식어 | 표시 | 규칙 |
|---|---|---|
| 고정 | 텍스트 배지 `고정`(ink-2, 11px) | 고정비 카테고리 거래가 있는 날. **카테고리색 점을 쓰지 않는다** — 주거 `#8b5cf6`·구독 `#a855f7`은 가정 보라 `#7A3FE4`와 같은 계열이라 8px 점에서 구분되지 않는다 |
| 이체 | 텍스트 배지 `이체` | 저축/투자·대출상환만 있는 날은 숫자 없이 배지만, 변동비도 있으면 숫자 + 배지 |
| 초과 | 막대가 트랙을 꽉 채우고 합계가 600 굵기 | 변동비 합계 > 하루 기준선. **주황 없음.** 초과분 `+500원`은 시트 둘째 줄과 aria에만 |
| 시점 | 오늘 = 배경 brand-soft · 미래 = 날짜 disabled, 숫자 자리 빈 칸, 눌러도 열리지 않음 · 지난달(스트립 앞 칸) = 요일 자리에 `8월` · 다음 달(스트립 뒤 칸, 9/27~10/3 주) = 요일 자리에 `10월`, 미래와 같이 disabled · 시작일 이전 = 옅은 빈 칸(`—` 없음) | 시작일(`quickEntry.since` = 새 앱 첫 실행일, 복원이면 복원일 · §12-24) 이전 칸은 `빈 날`로 세지 않는다. 소급 입력해도 시작일은 앞으로 가지 않는다 |
| 분류 전 | 칸에는 표시 없음 | 시트 목록·상태 줄·펼침 요약에서만 `카테고리 안 고른 N건` |

aria 문장 템플릿 하나: `{M}월 {D}일 {요일}, {기본 상태 문장}{, 고정비 있음}{, 이체 있음}{, 하루 기준선까지 {X}원 남음 | 하루 기준선보다 {X}원 많음}{, 오늘}`. 예: `9월 8일 화요일, 4건 37,000원, 다 적었다고 표시함, 하루 기준선까지 11,500원 남음, 오늘`.

**하루 기준선 — 출처를 한 줄로:** `limit.variableBudget ÷ daysInMonth` (`naviSpendingLimit`의 반환값, 수동 카테고리 한도는 반영되지 않음). 샘플: 총한도 216만 − 고정비 배분 70.5만(주거 55만 · 통신 5.5만 · 보험 8.5만 · 구독 1.5만) = 145.5만 ÷ 30 = **48,500원**. `variableBudget === 0`이면 기준선 `—`, 막대 없음. 직전 3개월 기록이 없는 달(`limit.personalized === false`)은 고정비 배분이 실제 청구액이 아니라 표준 비중 추정(총한도 × 0.33)이라 **기준선 `—`, 막대 없음**, 칸은 금액만(§12-5). 기준선은 저장하지 않으므로 고정비 청구액·한도·월급이 바뀌면 이번 달 모든 칸이 새 기준선으로 다시 그려집니다(§8 '기준선이 바뀜').

같은 홈에 세 가지 `하루`가 있습니다. 라벨을 고정합니다.

| 숫자 | 식 | 샘플 | 어디 | 라벨 |
|---|---|---|---|---|
| 하루 기준선 | `variableBudget ÷ 일수` — 이번 달 내내 상수 | 48,500원 | 달력 칸 막대 · 시트 둘째 줄 · 한도 화면 설명 | `하루 기준선 48,500원` |
| 앞으로 하루 | `remain ÷ 남은 일수` — 매일 변함 | 47,270원(104만 ÷ 22, 10원 반올림) | 홈 `이번 달 한도` 카드 | `앞으로 하루 47,270원` |
| 코치 | `limit.remain ÷ leftDays` — 위와 같은 값 | 47,270원 | 코치 카드 본문 | 문장 안에서도 `앞으로 하루 47,270원씩` |

**상태 줄 규칙:** 항상 한 문장, meta 11px ink-2, 평가어·감탄 없음. 우선순위: 저장 실패·충돌 > `8월 다시 마감 필요 ›` > 반복 중복 의심 > 기준선 변경 1회 안내 > 분류 전 강조 표시 > 오늘 요약(`오늘 4건 3.7만원 · 이번 달 기록한 날 7일`). 18시 이후 오늘에 변동비 거래가 1건 이상 있고 아직 닫지 않았으면 오늘 요약 뒤에 `· 9월 8일 다 적었어요 ›`를 **한 문장으로 합쳐** 1탭 경로가 실제로 보이게 합니다(`오늘 4건 3.7만원 · 9월 8일 다 적었어요 ›`). 강조 표시는 주황이 아니라 **600 굵기 + brand-soft 배경 필**입니다. `이번 달 빈 날 N일`은 펼침에서만, 시작일 이후만 셉니다. 달력 카드가 없는 홈(끈 사용자 · 1단계)에서는 같은 문구·같은 우선순위를 소비 탭 알림 줄이 보여 줍니다(§9-17).

### 3-4. 히어로와의 관계

- 히어로는 **자리·모양·문구 1px 불변.** `소비 기록하기`는 동작만 바뀌어 오늘 하루 시트를 홈 위에 엽니다(record intent = 하루 시트). 각주 `실수령 급여 기준 · 부수입·저축 이체·대출상환 제외`는 소비율의 근거 문장이라 조건부로 바꾸지 않습니다. `기록이 적어 예상 폭이 커요`는 완료 카드와 상태 줄에 둡니다.
- 월급 미입력이면 히어로 버튼은 지금처럼 `월급 입력하고 시작` 문구이되 동작은 하루 시트 열기(§12-4). 저장 뒤 완료 카드의 주 행동이 `월급 넣기 ›`라 다음 저장부터 히어로가 켜집니다.
- 소비율은 히어로에서만 display 크기입니다. 달력·시트·완료 카드에서는 body 크기 문장 안의 숫자로만 나옵니다.

### 4-2. 하루 시트

`BottomSheet`(SPEC §18) 변형. `app/page.tsx`의 다이얼로그 층에 마운트해 **탭 전환 없이 홈 위에** 뜹니다. 시트 이름은 `하루 시트`, 기존 소비 탭 시트는 그대로 `거래 추가`라고 부릅니다.

```
┌──────────────────────── 손잡이 ─────────────────────────┐
│ ‹   9월 8일 화요일 · 오늘   ›                       닫기 │  헤더 날짜 탭 → 주 선택기
│ 오늘 4건 3.7만원 · 하루 기준선 48,500원까지 11,500원 남았어요 │  둘째 줄 · 초과면 '하루 기준선보다 500원 많아요'
│                                                          │
│ 금액                                        [ 12,000 ]원 │  자동 포커스 · inputmode=numeric · 17px 우측 정렬
│ 1.2만원                                                  │  콤마 + 만원 읽기 병기
│ 최근 기록  [커피 4,500 ·카페/간식] [편의점 6,500 ·분류 전] [점심… │  가로 스크롤 · 8자 + … · 0개면 줄 숨김
│ 메모       [ 저녁                         ]        2/60   │
│ 카테고리                     나중에 분류   ·   저축·상환 › │  칩 줄 밖 고정 위치
│ [·식비][·카페/간식][·교통] │ [·식비][·카페/간식][·교통][·주거… │  앞 3칸 최근·빈도 슬롯 │ 고정 순서 13개
│ 수입·환불은 거래 추가에서 ›                                │  meta 링크 · 종류 미선택으로 인계
│                                                          │
│ 오늘 기록                                                 │  오늘·기록 없는 날 = 입력 우선(목록 아래)
│  ·카페/간식   커피                          4,500원       │  기록 있는 과거 날 = 목록 우선(3행) + '+ 추가' 점선 행
│  ·식비        점심                          9,000원       │
│   분류 전     편의점                        6,500원       │
│  + 1건 더 보기                                            │
│                       9월 8일 다 적었어요 (변동비 1건 이상) │
│ [                     저장                     ]          │  채운 Primary는 시트 안에서 이것 하나
│                        오늘은 안 썼어요 (변동비 0건일 때만) │
└──────────────────────────────────────────────────────────┘
```

규칙:

- **기본 날짜 = 오늘.** `한 건 더`로 이어지는 연속 입력 안에서만 날짜를 기억하고, 시트가 닫히면 오늘로 돌아옵니다. 날짜가 오늘이 아니면 헤더 날짜를 굵게(600) 보여 줍니다.
- **날짜 이동:** `‹ ›`는 하루씩(`›`는 오늘에서 멈춤). 헤더 날짜를 탭하면 **주 단위 선택기**(이번 달 + 지난달 전체)가 열립니다. 그 이전 달은 소비 탭 `거래 추가`로 안내합니다. 홈 시트의 범위는 이번 달 + 지난달입니다.
- **입력 우선 vs 목록 우선:** 오늘과 기록 없는 날은 금액에 자동 포커스. 기록이 있는 과거 날은 목록(스크롤 없이 3행)이 위, 금액 필드는 접혀 있고 `+ 추가` 점선 행을 누르면 펼쳐지며 포커스.
- **금액 입력은 네이티브 숫자 키보드**(`inputmode=numeric`, 기존 NumberInput 규칙 17px 우측 정렬·16px 이상). 커스텀 키패드(`000`·`만` 키)는 1단계에서 빼고 실기기 측정 뒤 별도 단계로(§12-16). 입력값 아래 `1.2만원` 읽기를 병기해 자릿수 오입력을 잡습니다.
- **메모 포커스 시** 저장 버튼을 네이티브 키보드 위 고정 행으로 옮기고, 포커스 해제 시 푸터로 복귀합니다. 60자 상한, 50자부터 카운터. 기존 60자 초과 메모는 그대로 열리고 저장도 되며 추가 입력만 막습니다(두 시트·반복 규칙 이름 공통).
- **기본 카테고리 = `분류 전`.** 색 칩 줄은 CATEGORIES 순서 고정 13개(저축/투자·대출상환 제외) 앞에 `최근·빈도 슬롯 3칸`을 둡니다. 슬롯은 최근 30일 수동 소비 거래(자동 생성·분류 전·이체 제외)의 카테고리별 건수 상위 3, 고정비 카테고리 포함, 동률은 최근 사용일 순, 부족하면 채워진 만큼만(0칸이면 구분선 없이 고정 13개부터 · §12-25). 슬롯 3칸만 바뀌고 나머지 위치는 고정입니다. `나중에 분류`와 `저축·상환 ›`는 칩 줄 밖, 카테고리 라벨 오른쪽 고정 위치라 360px 가로 스크롤에서도 밀려나지 않습니다.
- **최근 기록 칩**은 최근 30일 거래에서 메모+금액+카테고리가 같은 묶음을 빈도순 5개까지. 자동 생성 거래는 빼고, **분류 전 건은 `분류 전` 라벨을 달고 포함**합니다 — 메모만 적는 사용자도 칩을 쓸 수 있게(§12-22). 탭하면 금액·메모·카테고리를 채우고(분류 전 칩은 금액·메모만, 카테고리는 분류 전 유지) 저장은 사용자가 누릅니다. 칩이 0개면 줄 자체를 숨깁니다(첫 사용).
- **`저축·상환 ›`**는 날짜·금액·메모를 `initialDraft`로 들고 소비 탭의 `거래 추가`를 종류 `저축/투자` 미리 고른 채 엽니다(탭 전환 불가피, `record` intent에 `initialDraft`·`returnTo:'home'` 추가). 저장 뒤 홈으로 돌아와 완료 카드가 뜹니다(§12-18). **`수입·환불은 거래 추가에서 ›`**도 같은 인계이되 종류를 미리 고르지 않습니다(§9-5). 하루 시트는 일반 소비 전용입니다.
- **`다 적었어요`·`안 썼어요`(2단계):** 시트 안 `9월 8일 다 적었어요`는 시간과 무관하게 그 날짜에 변동비 거래가 1건 이상이면 보입니다(과거 날 시트도 같음). 18시 조건은 상태 줄에만 있습니다. `오늘은 안 썼어요`는 그 날짜에 **변동비 거래가 0건**이면 보입니다 — 통신비만 자동 생성된 25일에도 누를 수 있습니다.
- **닫기:** 스크림·`닫기`·손잡이·Android 뒤로가기(`navi-back` → Escape)·웹 뒤로가기 전부 **닫기**입니다(하루 시트만 해시 복원 규칙의 예외). 확인 대화는 없고, 같은 날짜 시트를 다시 열면 세션 안에서 초안이 복원됩니다. 스크림 상단 문구 `배경을 눌러 닫기 · 입력값은 남아요`.
- **샘플 모드:** `나중에 분류` 칩과 `다 적었어요`·`안 썼어요`를 숨기고, 기본 카테고리는 `거래 추가`와 같은 `식비`(칩 선택 상태로 표시)입니다. 헤더 `샘플 데이터에 저장돼요 · 내 데이터로 시작하면 사라져요 · 내 데이터로 시작 ›`, 첫 저장 전에 한 번 확인합니다.

### 4-3. 저장 직전 확인 — 고정비·이체인가요?

`저장`을 눌렀을 때 아래 조건이면 저장 대신 인라인 안내 한 줄이 뜹니다(한 번 더 `저장`을 누르면 그대로 저장).

- 분류 전 또는 변동비 색인데 금액이 **활성 반복 규칙의 금액 ±5%** 또는 메모가 규칙 이름과 같음 — 색 선택과 무관하게
- 또는 금액이 **월급의 10% 이상**(실수령 360만 → 36만원 이상)

```
고정비나 이체인가요?  [·주거/관리][·통신][·보험][·구독][저축·상환 ›]   그대로 저장
이 달 휴대폰 요금 55,000원은 25일에 자동으로 생겨요 · [이번 달 자동 생성 건너뛰기] [그대로 저장]
```

반복 규칙과 겹치는 경우의 선택지 `이번 달 자동 생성 건너뛰기`는 `settings.recurringExclusions`에 생성 예정 id `recurring:<ruleId>:<YYYY-MM>`를 **기존 형식 그대로** 미리 넣습니다. 같은 날 이미 자동 생성 건이 있으면 `같은 날 통신 55,000원(반복)이 이미 있어요 · [그래도 저장] [취소]`.

### 4-4. 완료 카드

저장이 끝나면 시트가 닫히고 홈 위에 완료 카드가 뜹니다. **전역 저장 토스트의 자리와 역할을 그대로 이어받는 Toast 변형**(SPEC §19)이며, `commit`에 `notice: 'quick'` 옵션을 넘겨 `이 기기에 저장했습니다.` 토스트를 생략합니다. 저장 확인 UI는 하나입니다.

```
┌ 저장했어요 · 9월 8일                                  닫기 ┐
│ 오늘 5건 4.9만원 · 소비율 57.9% → 58.2%                     │
│ [한 건 더]   [되돌리기]                                      │
└────────────────────────────────────────────────────────────┘
```

- **자동으로 닫히지 않습니다.** `닫기`·다음 저장·다른 탭 이동까지 유지 — 현행 되돌리기 수명과 같습니다. 되돌리기는 이 카드 하나뿐이고 대상은 전역 `undoState`(직전 1회분 전체 상태)입니다.
- **제목 3종, 카드는 하나:** 하루 시트 저장 `저장했어요` · 수정 모드 저장 `고쳤어요` · 분류하기 저장 `분류했어요 · 7건`. 뒤의 둘은 행동이 `되돌리기`뿐입니다(§12-2).
- **행동 슬롯 2개 = 주 행동 + `되돌리기`.** 주 행동은 기본 `한 건 더`이고, 월급 미입력이면 `월급 넣기 ›`가 그 자리를 대신합니다(다음 건은 오늘 칸으로). 그 밖의 링크는 셋째 줄 문장 안에 둡니다(§12-30).
- 반복 거래 자동 생성(focus·15분 타이머)과 `dataMode` 감지 저장은 `notice: 'silent'`로 commit해 **undoState와 문구를 갱신하지 않습니다.** `한 건 더` 중에 앱을 전환해도 되돌리기 대상은 사용자의 저장입니다.
- 사실만 씁니다. 초과·미달 평가어 없음, 색 없음. 둘째 줄의 소비율은 저장 전·후 `naviMetrics` 값입니다(편의점 12,000원 저장 → 4건 3.7만원이 5건 4.9만원, 57.9%가 58.2%). 월급 미입력이면 `소비율 —` 대신 주 행동이 `월급 넣기 ›`가 됩니다.
- 조건부 셋째 줄은 한 줄만, 우선순위는 이 순서: 마감된 달 `8월 다시 마감 ›` > 지난달 `8월 합계와 최근 3개월 평균이 바뀌어 이번 달 예상도 달라질 수 있어요` > 지난달 첫 입력 `기록이 적어 예상 방식이 바뀌어요` > 0~5시에 오늘로 저장 `어제로 옮기기 ›` > 분류 전 저장 `고정비면 분류해야 예상이 맞아요` > 고정비 색으로 저장 `매달 반복으로 만들기 ›` > 첫 달 `기록이 적어 예상 폭이 커요`.
- `한 건 더`는 같은 날짜로 비워진 시트를 엽니다.
- `dayLog` 저장(닫기·안 썼어요)은 카드 없이 **체크 표시 자체가 확인**입니다(`notice: 'silent'`). 실패·충돌일 때만 상태 줄에 문구가 뜹니다.

### 4-5. 소비율 미리보기 — 저장 전에는 보여 주지 않는다

시트 안에서 저장 전 소비율을 보여 주는 값은 정의상 `저장되지 않는 값`이라 원칙 5에서는 보라입니다. 원칙을 고치지 않고, **미리보기를 두지 않습니다.** 히어로 변화는 저장 뒤 완료 카드의 `57.9% → 58.2%`로만 봅니다. 대안(§12-9)으로 조건 문구 `저장하면 58.2%가 돼요`를 두는 경우에도 값은 가상 `AppState`(`saveTransaction(state, draft)` 결과)에 `naviMetrics`를 호출해 얻고 150ms 디바운스합니다. 단순 산술로 따로 계산하는 안은 없습니다 — 고정비 `max` 규칙과 첫 달 선형 외삽 때문에 저장 후 값과 어긋납니다.

### 4-6. 수정 모드

시트 목록의 행을 탭하면 같은 시트가 수정 모드로 바뀝니다.

- 금액 필드가 **전체 선택된 채 포커스**되어 타이핑이 값을 덮어씁니다(오타 수정 4탭).
- 헤더에 `‹ 어제로 · 다음 날로 ›` 날짜 이동. 잔액 연결이 없는 거래는 제한 없이, 연결 거래는 날짜 잠금.
- 잔액 연결이 있는 거래는 금액·메모·색만 바꿉니다. `saveTransaction`이 기존 링크로 잔액을 재계산하고 부족 예외가 나면 `연결된 계좌 잔액이 부족해요 · 거래 추가에서 확인`. 링크 추가·해제는 `거래 추가`에서만.
- 저장하면 완료 카드 `고쳤어요 · 9월 3일`, 행동은 `되돌리기`만(§4-4).
- 삭제는 기존 확인 대화. 반복 거래면 `recurringExclusions`에 등록됩니다.
- 분류 전 행의 `⋯` 메뉴에는 `매달 반복으로 만들기`가 없습니다.

## 5. 카테고리 — 색으로 지정 · 나중 분류

### 5-1. 색 ↔ 카테고리 매핑 규칙

요청하신 "카테고리는 색상으로 지정"은 하루 시트의 색 칩(색 점 8px + 이름)으로 구현합니다 — 색을 고르는 것이 곧 카테고리를 고르는 것이고, 이름을 붙여 색만으로 뜻을 전하지 않습니다. 달력 칸에는 카테고리색을 쓰지 않는데, 주거 `#8b5cf6`·구독 `#a855f7`이 가정 보라 `#7A3FE4`와 같은 계열이라 44px 칸의 8px 점으로는 구분되지 않고, 칸이 전할 정보는 변동비 합계 + 막대 하나로 끝나기 때문입니다.

| 규칙 | 내용 |
|---|---|
| 팔레트 | `lib/engine/constants.ts` 15색 그대로. 새 색 없음 |
| 칩 | 색 점 8px + 카테고리 이름. 색만으로 전달하지 않음(`colorNotAlone`) |
| 색이 쓰이는 곳 | 시트 칩 · 시트 목록 행 · 내역 · 차트. **달력 칸에서는 쓰지 않음** |
| 고정비 4개(주거/관리 · 통신 · 보험 · 구독) | 칩 줄에서 구분선 뒤에 모아 두고 칩 아래 `고정비예요 · 실제 청구액으로 저장돼요 · 막대에는 안 넣어요` |
| 이체 2개(저축/투자 · 대출상환) | 칩 줄에 없음. `저축·상환 ›`로 `거래 추가`에 인계 |
| 문구 | `색 안 고른`이 아니라 **`카테고리 안 고른 N건`** — 색을 구분하기 어려운 사용자도 쓸 수 있게 |

### 5-2. 분류 대기 — settings.quickEntry.uncategorized

`나중에 분류`로 저장한 거래는 **카테고리 `기타`**로 저장되고 id가 `settings.quickEntry.uncategorized` 배열에 들어갑니다. Transaction 형식은 다섯 필드 그대로입니다(`lib/engine/types.ts` 불변).

불변식 세 개(전부 `lib/navi-quick-entry.ts`에서):

1. **카테고리가 `기타`가 아니면 표식을 제거한다.** 하루 시트 수정 모드·분류하기·소비 탭 `거래 추가` 어느 경로로 바꿔도 같은 함수(`reconcileUncategorized`)가 `changeState` 직전에 돕니다.
2. **저장 직전 존재하는 id로 걸러 낸다.** 삭제·되돌리기·가져오기 충돌로 남은 유령 id는 저장할 때마다 빠집니다.
3. **표시는 실시간 교집합만.** `uncategorized ∩ transactions(category === '기타')`.

`골라서 가져오기`는 settings 네 키만 합치므로(`mergeNaviImport`) 가져온 분류 전 건은 영구 `기타`가 됩니다. 가져오기 화면에 그 사실을 씁니다(§8).

### 5-3. 계산 처리 — 사실 그대로

| 항목 | 계산에서 | 화면에 표시하는 것 |
|---|---|---|
| 소비 합계 · 한도 총액 · 하루 합계 | `기타`도 소비라 **즉시 정확** | `저장했어요` |
| 월말 예상 · 소비율 | `기타`는 변동비 → `cur.variable`에 들어감. 월세를 분류 전으로 두면 `hist.fixed`가 이미 월세를 예약하고 있어 예상이 최대 그 금액만큼 과대. 나중에 주거/관리로 바꾸면 `cur.fixed↑ · cur.variable↓`로 예상이 내려감 | 완료 카드·상태 줄 `고정비면 분류해야 예상이 맞아요` · 재분류 안내 `고정비 색으로 바꾸면 월말 예상과 하루 기준선이 다시 계산돼요` |
| 카테고리 한도 | `기타` 소진율에 들어감(엔진). 고정비 한도는 `max(3개월 평균, 이번 달 실제)`라 분류 전 금액은 거기 잡히지 않음 | 카테고리 화면 `기타` 아래 `분류 전 4건 3.2만원` 서브라인 |
| `기타 한도 초과` 경고 · 코치 `최대 카테고리 비중` | 엔진·어댑터는 그대로 `기타`로 판정 | 표시 계층에서 분류 전 금액을 뺀 사용량으로 다시 판정해 보여 줌(`navi-insights`는 보호 파일 아님 · 경고는 AlertsPanel에서 재판정). 크면 `분류 전 정리` 카드 |
| 다음 달 자동 배분 | `avgByCat`이 3개월 `기타` 평균을 그대로 써서 분류 전이 남은 채 달을 넘기면 다음 달 `기타` 배분이 커지고 식비 등이 줄어듦. `lib/engine`·`navi-current`가 보호 파일이라 **UI만으로는 못 빼냄** | 마감 모달 한 줄 `분류 전 4건 · 3.2만원이 기타로 들어가요 · 다음 달 한도 배분에도 기타로 들어가요 · 지금 분류 ›`. 근본 처리는 §12-8 결정 |
| 마감된 달의 분류 변경 | `close.spend`는 같아 재마감 경고 없음(비교 기준은 **spend 총액만**, `spending-analysis.tsx:695` 확인). 이번 달 `hist`는 바뀜 | 완료 카드 `마감값 구성이 달라졌어요 · 이번 달 예상이 다시 계산될 수 있어요` |

### 5-4. 분류하기 시트(3단계)

상태 줄 `카테고리 안 고른 7건 · 분류하기 ›`로 엽니다(달력 카드가 없으면 내역 필터 칩 `분류 전 7건`이 진입점). 같은 메모의 건은 묶음 행(`커피 ×4 · 18,000원`)으로, 오른쪽에 추천 칩 하나(최근 같은 메모의 카테고리). 추천은 **탭 없이는 채워지지 않습니다.** 하단 `7건 저장`은 `changeState` 한 번, id·date·amount·memo 보존, category만 바뀝니다. 저장 뒤 완료 카드 `분류했어요 · 7건`, 행동은 `되돌리기`만(§4-4, §12-2).

## 6. 데이터 모델 — 추가만, 백업 호환

```
settings.quickEntry {
  version: 1,
  since: "2026-09-01",                   ← 시작일. 새 앱 첫 실행일(복원이면 복원일). 이전 칸은 빈 날로 세지 않는다
  dayLog: {                              ← 날짜 키. 거래를 만들지 않는다
    "2026-09-06": { closed: true, noSpend: false, at: "2026-09-06T21:10:00+09:00" },   ← 스트립 6일 '0.5만 ✓'
    "2026-09-05": { closed: true, noSpend: true,  at: "…" }                            ← 그리드 5일 '0'
  },
  uncategorized: ["tx_…", "tx_…"]        ← 카테고리 '기타'인 거래 id. §5-2 불변식
}
homeLayout.cards   ["calendar", "nextGuide", "limit", "primaryGoal", "peer"]   ← v4 §6 형식 그대로, 값 "calendar"만 추가. 기본 배열이 이것으로 바뀜(§3-1)
settings.recurringExclusions             ← 기존 키·형식 그대로. '이번 달 자동 생성 건너뛰기'가 예정 id를 넣는다
```

- **Transaction · 반복 규칙 · 마감 · 잔액 연결 형식 불변.** 거래 id는 지금 생성 방식 그대로.
- **검증기 불변.** `isStoredState`는 모르는 settings 키를 보지 않으므로(`navi-storage.ts:174-246`) `quickEntry`를 검증기에 넣지 않습니다. 넣으면 항목 하나가 어긋날 때 상태 전체가 거부돼 복원이 실패합니다. 대신 `getQuickEntry(state)`가 `getRecurringRules`와 같은 방식으로 **느슨하게 읽어 잘못된 항목만 걸러 냅니다** — 날짜 키·boolean·string id가 아닌 항목은 빼고, `since`가 없거나 날짜가 아니면 오늘로 보정하며, 통째로 깨져 있으면 기본값.
- 백업 호환:

| 방향 | 결과 |
|---|---|
| 옛 백업 → 새 앱 | `quickEntry` 기본값(`since` = 복원일). 칸은 거래만. 닫은 표시·`0`·분류 전 없음 |
| 새 백업 → 옛 앱 | 모르는 settings 키 무시 → 통과. 분류 전은 `기타`로 보이고 `0` 표시만 사라짐 |
| 골라서 가져오기 | `quickEntry`는 안 따라옴. 가져온 분류 전 건은 `기타` |
| `quickEntry`가 깨진 백업 | 검증기 통과 → getter가 그 키만 기본값. 거래는 그대로 |

- 저장 경로는 전부 `changeState → materializeRecurringTransactions(withDetectedDataMode) → saveGate.run → saveNaviData`. `commit`에 `notice` 옵션(`'default' | 'quick' | 'silent'`)만 추가하고 되돌리기는 직전 1회분 전체 상태(닫기·분류도 함께 되돌려짐). Android 암호화 파일도 같은 JSON.
- **토큰:** 새 hex 없음. 칸은 `track` · `brand-soft` · `ink-2` · `ink-3` · `disabled`만 조합합니다. `dataPalette`는 엔진 색 거울이라 손대지 않습니다. 키가 필요하면 `component.calendar` 블록에 두고, 새 hex가 하나라도 생기면 `darken.py MAP`에 짝을 추가합니다(§9-13).
- **SPEC-COMPONENTS 신규 등록(치수는 허용 목록 값만):**

| 컴포넌트 | 기반 | 치수 |

## 7. 사용자 흐름과 유저 스토리

### 7-1. 흐름

앱의 주기는 한 줄입니다: **첫 실행 · 월급 · 홈 구성(달력이 기본 켜짐) → 매일 하루 시트 → 주말 분류하기 → 월말 마감 → 다음 달 하루 기준선(`personalized`).** 아래는 그 안의 기록 한 건입니다.

### 7-2. 상황별 유저 스토리

| 언제 | 하고 싶은 것 | 앱에서 |
|---|---|---|
| 첫 실행, 월급 미입력 | 설정보다 오늘 산 커피값부터 적고 싶다 | 오늘 칸을 누르면 기준선 없이도 시트가 열리고 저장된다. 완료 카드 `저장했어요 · 오늘 1건 0.5만원` + 주 행동 `월급 넣기 ›`. 히어로는 `—` 그대로이고, 월급을 넣으면 다음 저장부터 소비율이 켜진다 |
| 첫 실행, 홈 구성(v4) | 홈에 달력이 들어가는지 보고 고르고 싶다 | HomeSetup 목록 첫 행 `이번 달 달력`이 켜진 채 주 스트립 축소판이 보인다. 그대로 두면 히어로 아래 첫 카드로 나오고, 싫으면 여기서 끈다 |
| 첫 달 둘째 주 | 한 건 넣었더니 월말 예상이 튀어 놀라고 싶지 않다 | 이력이 없으면 선형 외삽이라 실제로 튄다. 완료 카드 셋째 줄 `기록이 적어 예상 폭이 커요`. 칸은 기준선 `—`라 막대 없이 금액만 |
| 매일 아침 | 어젯밤 택시비를 적고 싶다 | 어제 칸 → 숫자 → 저장. 어제 칸의 `—`가 `0.9만`으로 바뀐다 |
| 새벽 1시 | 방금 낸 술값이 오늘로 찍히는 걸 막고 싶다 | 오늘 시트 둘째 줄 `어젯밤 소비면 ‹ 로 어제로 바꿔요`. 그냥 저장했으면 완료 카드 `어제로 옮기기 ›` 한 번 |
| 매일 커피 | 매번 치기 싫다 | 오늘 칸 → 최근 기록 칩 `커피 4,500 ·카페/간식` → 저장. 3탭, 숫자 0 |
| 메모만 적는 사람 | 색은 안 고르고 메모로만 남기고 싶다 | `편의점` 메모 + 금액 → 저장. 다음부터 최근 기록 칩에 `편의점 6,500 ·분류 전`이 올라와 한 번에 채워지고, 카테고리는 분류 전 그대로다 |
| 계산대 앞 | 금액만 적고 싶다 | 색을 안 고르고 저장. `분류 전`으로 남고 소비 합계·한도 총액은 그 자리에서 정확하다. 월말 예상은 변동비 가정이라 완료 카드에 `고정비면 분류해야 예상이 맞아요` |
| 계산대 앞, 큰 금액 | 36만원짜리를 급히 넣는다 | 저장을 누르면 `고정비나 이체인가요?` 한 줄. `그대로 저장`이면 그대로 |
| 저녁 | 오늘 얼마나 넘었는지 알고 싶다 | 다섯 건째 편의점 12,000원을 넣으니 합계 49,000원. 오늘 칸 막대가 꽉 차고 시트 둘째 줄 `하루 기준선보다 500원 많아요`. 주황 없음 |
| 퇴근길 | 커피·점심·편의점을 한 번에 넣고 싶다 | 저장 → 완료 카드 `한 건 더` → 같은 날짜로 비워진 시트. 카드는 사라지지 않으니 천천히 눌러도 된다 |
| 밤 | 오늘 기록이 끝났다고 표시하고 싶다 | 18시 이후 상태 줄 `오늘 5건 4.9만원 · 9월 8일 다 적었어요 ›` 1탭 → 칸에 체크. 시트 안 버튼은 시간과 무관. 토스트 없음 |
| 안 쓴 날 | 빈칸으로 남기고 싶지 않다 | 오늘 칸 → `오늘은 안 썼어요`(변동비 0건일 때만) → 칸에 `—`가 아닌 `0`. 상태 줄 `오늘은 안 썼다고 표시했어요`. 소비율에는 영향 없음 |
| 25일, 통신비만 자동 생성된 날 | 변동비는 안 썼다고 표시하고 싶다 | 변동비 0건이라 `오늘은 안 썼어요`가 보인다 → 칸 `0` + `고정` 배지. 안 누르면 `—` + `고정` |
| 여행 뒤 | 5일이 비어 있는데 부담 없이 채우고 싶다 | 펼침에만 `이번 달 빈 날 5일 · 빈 날은 —로 남아요`. 기억나는 날은 적고 나머지는 `—`로 둔다. 연속 카운터가 없어 잃을 것도 없다 |
| 20일에 설치 | 첫날부터 밀린 숙제를 보고 싶지 않다 | 시작일(첫 실행일) 이전 칸은 옅은 빈 칸. `빈 날`은 그 뒤부터만 세고, 8월 20일을 소급 입력해도 시작일은 앞으로 가지 않는다 |
| 월세 낸 날 | 이 돈이 하루 막대를 터뜨리지 않길 바란다 | 주거/관리 색을 고르면 `고정비예요 · 실제 청구액으로 저장돼요 · 막대에는 안 넣어요`. 칸은 `고정` 배지 하나. 청구액이 3개월 평균보다 크면 상태 줄 1회 `고정비가 바뀌어 하루 기준선이 48,500 → 46,800원이 됐어요` |
| 월세 낸 날, 다음 달부터 | 매달 자동이면 좋겠다 | 완료 카드 셋째 줄 `매달 반복으로 만들기 ›` → 규칙 다이얼로그가 이름·금액·카테고리·결제일로 채워지고 시작 월은 다음 달. 이름이 비면 저장 불가 |
| 통신비를 20일에 손으로 | 25일에 두 번 잡히지 않길 바란다 | 색을 안 골라도 금액이 규칙과 같아 `이 달 휴대폰 요금 55,000원은 25일에 자동으로 생겨요 · [이번 달 자동 생성 건너뛰기]`. 놓쳤으면 25일 이후 상태 줄 `통신 반복 건이 두 번 잡혔을 수 있어요 · 확인 ›` |
| 적금 이체한 날 | 소비로 잡히지 않길 바란다 | `저축·상환 ›` → 금액·메모를 들고 `거래 추가`가 저축/투자로 열린다 → 저장 → 홈으로 돌아오고 칸에는 `이체`만 |
| 환불받은 날 | 카드 취소액을 적고 싶다 | 하루 시트에는 없다. `수입·환불은 거래 추가에서 ›`로 날짜·금액·메모를 들고 넘어가고, 저장 뒤 홈으로 돌아온다 |
| 지난주 오타 | 45,000원을 4,500원으로 고치고 싶다 | `펼치기 ▾` → 그 칸 → 행(금액 전체 선택) → 타이핑 → 저장. 4탭. 완료 카드 `고쳤어요` |
| 방금 오타 | 바로 물리고 싶다 | 완료 카드 `되돌리기`. 카드는 닫기 전까지 남는다 |
| 잘못된 날 | 지우고 싶다 | 칸 → 행 → `삭제` → 확인. 반복 거래면 제외 목록에 남는다 |
| 어제인데 오늘로 저장 | 옮기고 싶다 | 행 → 수정 모드 헤더 `‹ 어제로` → 저장. 재타이핑 없음 |
| 주말 | 카테고리 안 고른 7건을 한 번에 치우고 싶다 | 분류하기 시트에서 `커피 ×4`는 추천 칩 한 번, 나머지 3건은 개별 → `7건 저장` → 완료 카드 `분류했어요 · 7건` |
| 28일 | 마감 전에 정리하고 싶다 | 상태 줄이 굵게 `카테고리 안 고른 4건 · 월말 전에 정리 ›`. 주황 아님 |
| 10월 2일 | 9월 것이 남았다 | 상태 줄 `9월 분류 전 4건 · 마감 전에 정리 ›` → 9월 분류하기 시트 |
| 다음 달 초, 마감 | 분류 전이 기타로 들어가는 걸 알고 마감하고 싶다 | 마감 모달 위 한 줄 `분류 전 4건 · 3.2만원이 기타로 들어가요 · 다음 달 한도 배분에도 기타로 들어가요 · 지금 분류 ›` |
| 8월 마감 뒤 | 빠뜨린 8월 거래를 넣고 싶다 | 시트 헤더 날짜 탭 → 주 선택기에서 8월 20일 → 헤더 `8월 기록이에요 · 마감한 달이라 저장하면 다시 마감해 주세요` → 저장 → 완료 카드 `8월 합계와 최근 3개월 평균이 바뀌어 이번 달 예상도 달라질 수 있어요 · 8월 다시 마감 ›`. 홈 상태 줄에 `8월 다시 마감 필요 ›`가 재마감 전까지 남는다 |
| 폰 교체 | 백업을 복원하면 닫은 표시·분류 전이 살아 있길 바란다 | 전체 복원은 그대로 돌아온다. 백업 안내 `닫은 날 표시와 분류 전 표시도 함께 저장돼요` |
| 360px 폰 | 칸 숫자와 시트가 잘리지 않길 바란다 | 칸 44.6×56에 `4.7만`, 시트는 목록 3행 + 저장 버튼까지 보이고 메모 포커스 시 저장 버튼이 키보드 위로 온다 |
| 글자를 크게 쓰는 사람 | 시스템 글자 확대에서도 칸이 깨지지 않길 바란다 | 칸 글자는 줄이지 않는다. 칸 높이가 늘고, 넘치면 `4만`처럼 소수를 버리고, 그래도 넘치면 숫자 대신 막대·배지만. 숫자는 시트와 aria에 있다 |

## 8. 예외 케이스

| 상황 | 처리 | 화면 문구 |
|---|---|---|
| 과거 날짜(이번 달) | 칸 터치 → 그 날짜로 시트, 피커 없음. 저장하면 spend·월말 예상·히어로 즉시 재계산 | 헤더 `9월 3일 목요일`(어제까지만 `어제`) |
| 지난달 날짜(스트립 앞 칸 · 주 선택기) | 요일 자리에 `8월`. 그 달 기준선이 없으므로 막대 없이 금액만. 저장하면 8월 합계와 `hist`(직전 3개월 평균)가 바뀌어 **이번 달 월말 예상·히어로·카테고리 한도가 다시 계산될 수 있음.** 직전 3개월이 비어 있던 사용자는 `hist null → 값`으로 예상 공식 자체가 바뀜 | 헤더 `8월 기록이에요 · 8월 소비에 들어가요` · 완료 카드 `8월 30일에 저장했어요 · 8월 합계와 최근 3개월 평균이 바뀌어 이번 달 예상도 달라질 수 있어요`(히어로가 바뀌면 `57.9% → 58.4%` 그대로 표시) · 첫 입력이면 `기록이 적어 예상 방식이 바뀌어요` |
| 다음 달 날짜(스트립 뒤 칸, 9/27~10/3 주) | 요일 자리에 `10월`. 미래 날짜와 같이 disabled, 눌러도 열리지 않음. 그리드에는 나오지 않음(이번 달만) | — |
| 마감된 달 | 저장은 막지 않음. 마감 수입·잔액·스냅숏은 그대로라 재마감 안내. 재마감 경고는 `closed.spend !== spendOf().spend`(총액 비교)일 때만이라 분류만 바꾸면 경고 없음. 분류로 고정/변동 분할이 바뀌면 약한 안내. 이번 달 `hist`는 바뀜 | 헤더 `마감한 달이에요 · 저장하면 마감값과 달라지니 다시 마감해 주세요` · 완료 카드 `8월 다시 마감 ›` · 홈 상태 줄 `8월 다시 마감 필요 ›`(재마감 전까지) · 분류만 바꾸면 `마감값 구성이 달라졌어요 · 이번 달 예상이 다시 계산될 수 있어요` |
| 미래 날짜 | 월 그리드에서만 보임. 날짜 disabled, 숫자 자리 빈 칸, 눌러도 열리지 않음. 시트 `›`는 오늘에서 멈춤. 구버전 데이터의 미래 거래는 금액이 보이고 수정·삭제만 허용 | 상태 줄 3초 `아직 오지 않은 날은 적을 수 없어요` |

## 11. 완료 기준

- [ ] 아무것도 안 고르면 홈에 `이번 달 달력` 카드가 히어로 바로 아래 첫 카드로 보이고, 기본 5카드가 §3-1과 같다(`순자산 대비 소비`는 HomeSetup에서 다시 켤 수 있음). 이미 저장된 홈 구성은 바뀌지 않는다. 끄면 카드만 사라지고 히어로 `소비 기록하기`는 오늘 시트를 연다
- [ ] 월급 입력 상태에서, 홈에서 오늘 커피 저장까지 2탭 + 숫자, 탭 전환 0, 저장 후 홈에 그대로 있고 완료 카드에 소비율 전·후가 보인다(탭 수 정의는 §4-1)
- [ ] 월급 미입력 상태에서는 저장이 되고 완료 카드 주 행동이 `월급 넣기 ›`다
- [ ] 최근 기록 칩으로 3탭, 숫자 0. 분류 전 건도 `분류 전` 라벨 칩으로 쓸 수 있다
- [ ] 어제·그저께 기록에 날짜 피커 없음. 지난달은 헤더 날짜 탭의 주 선택기로
- [ ] 시트에 거래 종류·잔액 반영·계좌 선택이 없고, 저축·상환·수입·환불은 `거래 추가`로 값을 들고 넘어갔다가 홈으로 돌아온다
- [ ] 미입력 칸은 `—`, `안 썼어요`는 `0`, 둘은 끝까지 다른 상태. 고정비·이체만 있는 날은 `—` + 배지. `안 썼어요`는 변동비 0건이면 누를 수 있다. 0원 거래는 만들지 않는다. `안 썼어요`는 소비율·월 비교·코치·경고에 영향이 없고 화면에 그 사실을 표시한다
- [ ] 칸 숫자·막대는 변동비만. 고정비는 `고정`, 이체는 `이체` 텍스트 배지. **셀에 카테고리 색 사용 없음**
- [ ] 칸 숫자는 한 형식(`0.9만` · `3.7만` · `12.5만` · `120만` · `1,200만` · `1.2억`), 반올림은 500원 올림·10원 반올림 한 규칙, 기본 글자 크기에서 7자리 금액도 44px 안에 들어간다. 글자 확대 시 글자를 줄이지 않고 §8 넘침 규칙을 따른다
- [ ] 주 스트립은 오늘이 속한 일~토, 펼침 토글은 `펼치기 ▾`/`접기 ▴`이고 이번 주가 두 번 그려지지 않는다. 미래 칸과 다음 달 칸은 disabled에 숫자 자리가 빈 칸이다
- [ ] 화면당 display 숫자 하나(히어로), 그림자 카드 하나, 채운 Primary 하나(`소비 기록하기` · 시트 안은 `저장`)
- [ ] 달력·시트·완료 카드 어디에도 보라·점선 없음. 보라는 `저장되지 않는 가정` 카드에서만. 저장 전 소비율 미리보기 없음
- [ ] 주황은 히어로의 월 목표 초과에만. 칸의 기준선 초과는 막대 꽉 참 + 숫자, 분류 전 강조 표시는 굵기 + brand-soft
- [ ] 색만으로 전달하는 상태 없음 — 칩은 점 + 이름, 칸은 막대 + 숫자, 빨강 없음
- [ ] 상태 줄은 항상 한 문장, 평가어·알림 없음. 18시 이후 `다 적었어요`는 오늘 요약 문장에 합쳐 1탭으로 보인다. 연속 카운터 없음, `이번 달 기록한 날 N일`은 수동 변동비 거래 1건 이상인 날만. 달력 카드가 없으면 같은 안내가 소비 탭 알림 줄에 뜬다
- [ ] 완료 카드는 사실만(N건 · 합계 · 소비율 전후), 색 없음, 자동 닫힘 없음. 제목 3종(저장·고침·분류)에 카드는 하나, 행동 슬롯은 주 행동 + `되돌리기`. 되돌리기 진입점은 하나이고 수명은 현행(닫기·다음 저장까지). 자동 생성 저장은 undoState를 갱신하지 않는다

- [ ] 고정비 색으로 바꾸거나 지난달에 저장하면 히어로가 바뀔 수 있고, 완료 카드가 그 변화를 숨기지 않는다
- [ ] 분류하기에서 같은 메모 4건이 한 탭에 정해지고, 추천은 탭 없이는 채워지지 않는다
- [ ] 저장·닫기·분류 전부 `changeState → saveGate` 경로, 저장 중 inert
- [ ] 옛 백업이 그대로 열리고, 새 백업을 옛 앱이 열어도 거래가 그대로다. `quickEntry`가 깨져도 검증기를 통과하고 getter가 정화한다
- [ ] `lib/engine` 변경 0 · IMPLEMENTATION-PLAN §2 보호 파일 변경 0(SHA-256 동일) · 계산 결과 변화 0 · 거래 id·백업 형식·반복 규칙 형식 불변
- [ ] 기존 테스트 전부 통과 + 새 케이스 추가. pnpm typecheck / test / build 통과
- [ ] 360×640에서 본문 가로 스크롤 없음, 칸 터치 44 이상(44.6), 메모 포커스 시 저장 버튼이 키보드 위에 보인다
- [ ] 메모 60자 상한은 편집에만 적용. 기존 초과 메모는 저장 가능, 두 시트와 반복 규칙 이름 공통
- [ ] 칸은 button, 화살표 이동, focus ring 3px, aria 문장 템플릿 하나. 하루 시트는 Android 뒤로가기·Escape로 닫힌다
- [ ] 라이트·다크 모두 토큰 값으로 렌더, 새 hex 0, darken.py 산출과 어긋나지 않음
- [ ] 비행기 모드에서 전부 동작. 로그인·서버·외부 API 없음

- **칸 숫자를 1만 미만은 원 단위(`8,900`), 1만 이상은 만 단위로 섞는 안(ux):** 한 그리드 안에 단위가 둘이면 자릿수 비교가 흔들려 만 단위 소수 한 자리 한 형식으로 고정했습니다(feasibility 지적과 같은 결론). 합계 문장도 같은 형식이라 `오늘 1건 0.5만원`처럼 읽힙니다.
